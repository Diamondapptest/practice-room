# NOTIS ห้องซ้อมให้คำปรึกษา: คู่มือเปิดใช้งาน

เว็บฝึกให้คำปรึกษากับผู้รับบริการจำลอง ใช้ AI ของ Google (Gemini) แบบฟรี วางเว็บบน Vercel แบบฟรี และเก็บข้อมูลด้วย Upstash Redis แบบฟรี

---

## อัปเดตเวอร์ชัน 3 (ปรับตามเอกสาร Clinical QA Audit)

- **สภาวะภายในผู้รับบริการ:** ความไว้ใจ ความวิตกกังวล การตั้งการ์ด และความเข้าใจตนเอง เปลี่ยนทุกข้อความตามวิธีที่ผู้ฝึกคุย ข้อมูลที่ซ่อนจะเปิดเผยเมื่อความไว้ใจถึงเกณฑ์
- **คัดกรองความปลอดภัยแยกจากการเล่นบท:** ถ้าผู้ฝึกดูเหมือนกำลังพูดถึงความทุกข์ของตัวเองจริง ระบบจะหยุดการฝึกและแสดงเบอร์ 1323 / 1669 (บันทึกเหตุการณ์ไว้แบบไม่ระบุตัวตน ดูได้ที่ `type=safety`)
- **โหมดผู้คุมการฝึก:** ปุ่ม "ขอคำชี้แนะ" ระหว่างเซสชัน ได้ 3 ครั้งต่อรอบ ชี้โอกาสที่พลาดโดยไม่บอกคำตอบ
- **ประเมิน 9 สมรรถนะ** ตามแบบฟอร์มผู้สอน พร้อมเช็ก 5 ขั้นของเซสชัน จุดที่ควรระวัง สมมติฐานเบื้องต้น (ไม่ยืนยันการวินิจฉัย) กราฟสภาวะ บทสนทนาพร้อมป้ายอธิบายรายข้อความ และคำถามทบทวนตัวเอง
- **เตรียมตัวก่อนฝึก:** วัตถุประสงค์การเรียนรู้และโครงสร้างเซสชันที่แนะนำในแฟ้มเคส
- **บันทึกผลประเมินเป็น PDF** ได้จากหน้าผลประเมิน

วิธีอัปเดต: อัปโหลด**ของข้างในโฟลเดอร์ทั้งหมด**ทับใน GitHub เหมือนครั้งก่อน (มีไฟล์ใหม่ `api/supervise.js`) ไม่ต้องตั้งค่าอะไรเพิ่ม

## อัปเดตเวอร์ชัน 2 (สำหรับคนที่เปิดเว็บเวอร์ชันแรกไปแล้ว)

เวอร์ชันนี้เพิ่ม
- หน้าต่างขอความยินยอมก่อนเริ่มฝึก และข้อความคุ้มครองทางกฎหมาย
- ปุ่ม "ประเมินการฝึก" (เดิมชื่อ "ขอฟีดแบ็ก")
- จำกัดวันละ 3 รอบต่อคน รวมทุกตัวละคร
- แบบสอบถามหลังประเมิน และดาวน์โหลดผลเป็นไฟล์ Excel/Sheets ได้

ทำ 4 ขั้นนี้ตามลำดับ

**ขั้นที่ 1: อัปโหลดไฟล์ใหม่ขึ้น GitHub**
1. เปิด repository `practice-room` บน GitHub แล้วกด **Add file > Upload files**
2. ลาก **ของข้างใน** โฟลเดอร์ `practice-room` (เวอร์ชันใหม่) ไปวางทั้งหมด คือโฟลเดอร์ `api`, `public` และไฟล์ `package.json`, `vercel.json`, `README.md` ไฟล์ชื่อซ้ำจะถูกแทนที่ให้เอง
3. กด **Commit changes** แล้ว Vercel จะอัปเดตเว็บให้อัตโนมัติภายใน 1–2 นาที

**ขั้นที่ 2: สร้างฐานข้อมูลฟรี (Upstash Redis)**
1. ใน Vercel เปิดโปรเจกต์ `practice-room` แล้วกดแท็บ **Storage**
2. กด **Create Database** (หรือ **Browse Marketplace**) แล้วเลือก **Upstash** > **Upstash for Redis**
3. เลือกแพ็กเกจ **Free** ตั้ง Region ใกล้ไทย เช่น Singapore แล้วกดสร้าง
4. เมื่อระบบถามว่าจะเชื่อมกับโปรเจกต์ไหน เลือก `practice-room` และติ๊กทุก Environment แล้วกด **Connect**
   ระบบจะเพิ่มค่า `KV_REST_API_URL` และ `KV_REST_API_TOKEN` ให้เอง ไม่ต้องพิมพ์

ถ้าข้ามขั้นนี้ เว็บยังใช้ได้ แต่การจำกัด 3 รอบจะนับได้แค่ในเบราว์เซอร์ (ล้างข้อมูลเบราว์เซอร์ก็ได้รอบคืน) และจะไม่มีแบบสอบถาม

**ขั้นที่ 3: ตั้งค่าเพิ่ม (Settings > Environment Variables)**

| Key | ใส่อะไร | หมายเหตุ |
|---|---|---|
| `CONTACT_EMAIL` | อีเมลที่ใช้รับคำขอดูหรือลบข้อมูล | แสดงในหน้าต่างความยินยอม ควรใส่ตามหลัก PDPA |
| `ADMIN_KEY` | รหัสยาวๆ ที่คุณตั้งเอง เช่น `nsavoir-7Kq29x` | ใช้ดาวน์โหลดผลแบบสอบถาม ห้ามบอกใคร |
| `ACCESS_CODE` | **ลบทิ้ง** | ถ้าอยากให้ใครก็เข้าได้โดยไม่ต้องใส่รหัส |

**ขั้นที่ 4: Redeploy**
ไปที่แท็บ **Deployments** กด **⋯** ที่รายการบนสุด แล้วเลือก **Redeploy** เพื่อให้ค่าใหม่มีผล

## ดาวน์โหลดผลแบบสอบถามและผลประเมิน

เปิดลิงก์เหล่านี้ในเบราว์เซอร์ (เปลี่ยน `รหัสของคุณ` เป็นค่า `ADMIN_KEY`) ไฟล์ CSV จะดาวน์โหลดลงเครื่อง แล้วเปิดด้วย Google Sheets หรือ Excel ได้

- แบบสอบถาม: `https://practice-room-mu.vercel.app/api/results?type=surveys&key=รหัสของคุณ`
- ผลประเมินและบทสนทนา: `https://practice-room-mu.vercel.app/api/results?type=evaluations&key=รหัสของคุณ`

คอลัมน์ในไฟล์แบบสอบถาม

| คอลัมน์ | ความหมาย |
|---|---|
| time_th | วันเวลาตามเวลาไทย |
| caseId | เคสที่ฝึก (burnout = คุณมายด์, lowmood = คุณต้น, family = คุณสุดา) |
| rating | ความพอใจโดยรวม 1–5 |
| realistic | ความสมจริงของตัวละคร 1–5 |
| useAgain | จะกลับมาใช้อีกไหม |
| pay | ยินดีจ่ายเดือนละเท่าไร |
| role | สถานะของผู้ตอบ |
| comment | ความเห็นเพิ่มเติม |
| user | รหัสผู้ใช้แบบสุ่ม ใช้นับว่าคนเดียวกันตอบกี่ครั้ง ระบุตัวตนไม่ได้ |

## การนับรอบทำงานอย่างไร

- **หนึ่งรอบ** = การเริ่มคุยกับตัวละครหนึ่งครั้ง นับเมื่อผู้ฝึกส่งข้อความแรก
- เลือกตัวละครไหนก็ได้ แต่รวมกันไม่เกิน 3 รอบต่อวัน
- การกด "เริ่มใหม่" หรือเปลี่ยนตัวละครหลังส่งข้อความไปแล้ว จะนับเป็นรอบใหม่เมื่อส่งข้อความแรกของรอบนั้น
- การประเมินการฝึกไม่นับรอบเพิ่ม
- รีเซ็ตเวลาเที่ยงคืนตามเวลาไทย
- ระบบจำผู้ใช้ด้วยรหัสสุ่มในเบราว์เซอร์ คนที่ตั้งใจเลี่ยงจริงๆ (เปลี่ยนเบราว์เซอร์หรือล้างข้อมูล) ยังทำได้ แต่จะติดเพดานต่อเครือข่าย ถือว่าพอสำหรับช่วงทดลอง

## ติดตั้งครั้งแรก (ถ้ายังไม่เคยเปิดเว็บ)

1. **ขอ API key ฟรี:** เข้า aistudio.google.com แล้วสร้างโปรเจกต์ในหน้า Projects จากนั้นไปที่ API Keys > Create API key
2. **อัปโหลดขึ้น GitHub:** สร้าง repository แบบ **Private** แล้วใช้ "uploading an existing file" ลากของข้างในโฟลเดอร์ขึ้นไป
3. **Vercel:** Add New > Project > Import repository > Framework Preset: **Other** > ใส่ `GEMINI_API_KEY` ใน Environment Variables > Deploy
4. ทำขั้นที่ 2–4 ของหัวข้อ "อัปเดตเวอร์ชัน 2" ด้านบน

| ไม่มีแบบสอบถามหลังประเมิน | ยังไม่ได้เชื่อม Upstash หรือยังไม่ได้ Redeploy หลังเชื่อม |

ดูรายละเอียดข้อผิดพลาดได้ที่ Vercel > Project > **Logs**

## เรื่องข้อมูลและกฎหมาย

- ข้อความในหน้าต่างความยินยอมและท้ายเว็บ เขียนให้สั้นและครอบคลุมเรื่องหลักตาม PDPA แต่ยังไม่ได้ผ่านการตรวจโดยนักกฎหมาย ก่อนเปิดขายจริงควรให้นักกฎหมายตรวจอีกครั้ง
- ถ้าแก้ข้อความความยินยอม ให้เปลี่ยนค่า `CONSENT_VERSION` ใน `public/index.html` เพื่อให้ผู้ใช้เดิมเห็นหน้าต่างใหม่และยินยอมอีกครั้ง
- บริการฟรีของ Google อาจนำข้อความไปใช้พัฒนาโมเดล ซึ่งระบุไว้ในหน้าต่างความยินยอมแล้ว เมื่อเริ่มเก็บเงิน ควรเปลี่ยนเป็นแบบเสียเงินที่ไม่นำข้อมูลไปใช้
- ระบบเก็บบันทึกล่าสุดไม่เกิน 5,000 รายการต่อประเภท ถ้าจะลบข้อมูลทั้งหมด ไปที่หน้า Upstash ของฐานข้อมูล แล้วใช้คำสั่ง Flush / Delete keys
- ข้อมูลส่วนที่ซ่อนของแต่ละเคสเก็บไว้ฝั่งเซิร์ฟเวอร์ (`api/_cases.js`) ผู้ฝึกเปิดดูจากเบราว์เซอร์ไม่ได้

```
practice-room/

├── api/_store.js       ส่วนที่คุยกับฐานข้อมูล
├── package.json
└── vercel.json
```
